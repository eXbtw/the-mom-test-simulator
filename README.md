# The Mom Test Simulator

Тренажёр навыков проблемных интервью (кастдева) по методологии
["Спроси маму"](https://momtestbook.com/) Роба Фицпатрика.

Пользователь ведёт диалог с AI-персоной (респондентом). Параллельно
второй AI-агент в реальном времени оценивает вопросы интервьюера и
начисляет штрафы/баллы за наводящие и гипотетические вопросы, питчинг
и поощряет открытые вопросы о прошлом опыте.

## Зачем этот проект

Большинство тренажёров "поговори с AI-персоной" останавливаются на
самом диалоге — это может продемонстрировать модель, но не учит
навыку. Ставка здесь сделана на то, что диалог — это сырьё, а не
продукт: каждая реплика интервьюера тегируется типом ошибки, история
сессий копится локально, и поверх неё считается персональный профиль
слабых мест, архетип интервьюера и чек-лист перед реальным интервью.
AI генерирует персон и оценивает реплики; вся "тренерская" логика —
профиль, чек-лист, стрики, ачивки — чистые функции без AI-вызовов,
это дешевле, быстрее и детерминированнее.

Несколько продуктовых решений, которые не очевидны из кода:

- **Доверие персоны — скрытое.** Ответы респондента зависят от того,
  насколько корректно ему задают вопросы (наводящие/гипотетические
  вопросы получают уклончивый ответ, питчинг — отстранённый, открытые
  вопросы о прошлом — реальную боль), плюс накопленное доверие делает
  респондента более закрытым после серии плохих вопросов. Отдельный
  видимый "счётчик доверия" в интерфейсе сознательно не добавлялся —
  эффект должен ощущаться через сам разговор, а не через ещё один
  виджет на экране.
- **Никакой БД и аккаунтов.** История, сохранённые персоны и
  напоминание о реальном интервью живут в `localStorage`. Это
  осознанный компромисс ради нулевой инфраструктуры: полноценная
  система аккаунтов с напоминаниями по email потребовала бы auth,
  БД и cron — реализуемо на бесплатных тарифах, но кратно увеличивает
  поверхность проекта ради фичи, которая не является ядром ценности.
- **Фолбэк между моделями Gemini.** Бесплатная квота Gemini
  исчерпывается в реальности, поэтому `api/_gemini.js` перебирает
  список моделей при квотной ошибке, а не падает на первом отказе.

## Стек

- React + Vite, Tailwind CSS v4, lucide-react
- Vercel Serverless Functions (`/api`) как прокси к Google Gemini —
  API-ключ живёт только на сервере и не попадает в клиентский код
- Vitest — юнит-тесты на всю "тренерскую" логику (`src/utils`)

## Архитектура

```
Browser (React SPA, localStorage)
   │ fetch /api/*
   ▼
Vercel Serverless Functions (api/*.js)
   │ rate-limit per IP → callGemini()
   ▼
Google Gemini API (модель с фолбэком при исчерпании квоты)
```

Никакого своего бэкенда/БД: `/api/*` — это тонкий прокси, который
прячет API-ключ и ограничивает частоту запросов. Всё, что выглядит
как "состояние пользователя" (история, стрики, профиль слабых мест,
архетип), — вычисляется на клиенте поверх `localStorage`.

## Статус

Все три экрана из PRD реализованы: онбординг (B2B/B2C → категория →
респондент) → рабочий экран (чат + live-дашборд) → итоги сессии с
разбором ошибок. Онбординг предлагает 6 готовых персон, конструктор
по нише (`/api/persona-builder`) и режим «Проверь свою идею»
(`/api/idea-persona`) — описываете свой реальный продукт, и Gemini
сам определяет B2B/B2C и подбирает респондента с болью из проблемного
пространства идеи, не зная о самом решении. Все AI-эндпоинты
используют один и тот же Gemini-провайдер с фолбэком между моделями
при исчерпании дневной квоты (`api/_gemini.js`).

Поверх истории сессий (`src/utils/`) считаются: стрики и ачивки
(`achievements.js`), профиль слабых мест и архетип интервьюера
(`weaknessProfile.js`), скрытое доверие персоны (`trust.js`) —
всё это чистые функции, покрытые тестами.

## Разработка

Только фронтенд (без вызовов AI — запросы к `/api/*` будут падать):

```bash
npm install
npm run dev
```

Полноценный локальный запуск с работающими AI-эндпоинтами:

1. Получите бесплатный ключ в [Google AI Studio](https://aistudio.google.com/apikey).
2. Скопируйте `.env.example` в `.env` и впишите `GEMINI_API_KEY`.
3. Запустите:

```bash
npm run dev:full
```

Это поднимет Vite (порт 5173) и локальный API-сервер (порт 8787,
`server/dev-api.js` — переиспользует те же хендлеры из `/api`), Vite
проксирует `/api/*` на него. Открывайте `http://localhost:5173`.

(Раньше здесь использовался `vercel dev`, но он не поднимает свой
прокси-слой поверх Vite 8 / Node 24 и просто зависает — поэтому для
локальной разработки используется `server/dev-api.js`. На деплое на
сам Vercel это не влияет, там `/api` работает как обычно.)

## Тесты и CI

```bash
npm run lint   # oxlint
npm run test   # vitest — вся логика в src/utils
npm run build  # vite build
```

Все три команды прогоняются в GitHub Actions
(`.github/workflows/ci.yml`) на каждый push и pull request в `main`.

## Деплой

Проект деплоится на [Vercel](https://vercel.com) как есть — Vite-фронтенд
и `/api` определяются автоматически. Не забудьте добавить `GEMINI_API_KEY`
в Environment Variables проекта на Vercel.
